A long working session driving simble against a live Android 14 emulator over
netsim. Most of the value is in the **interop bugs found**: things that passed
every unit test and still failed against a real stack. Read the "Lessons"
section before trusting any claim about what works.

State at handoff: **1024 tests passing, 0 failing, clippy clean**, native and
wasm builds green.

## 1. What landed

### MCP surface (agent-facing)
- **`example` tool** — serves named, ready-to-run Rhai device scripts so an
  agent with no repo access can build a device. This is what makes the
  "fetch a script → `add_peripheral` → it's on the air" loop work.
- **`lookup` tool** — the Bluetooth SIG assigned numbers, vendored and
  generated into `src/gatt/sig_names.rs` (76 services, 511 characteristics,
  24 descriptors). Name→UUID and UUID→name. `status`/`scan`/`connect` output
  is now annotated with SIG names instead of bare hex.
- **`write` tool** — a real central write, the knob for settable devices
  (control points, setpoints, alert levels).
- **`scan` dedup** — one entry per advertiser with a `reports` count. It used
  to return the raw backlog (232 reports / 57 KB in one call), which can
  exceed an agent's tool-result limit outright.
- **`run_on("netsim")`** — wired. Scripted peripherals join the emulator's
  Bluetooth ether, one WebSocket per device.

### Architecture
- **`src/device/host.rs` (`LeHost`)** — the LE host layer, extracted out of
  `ScriptedPeripheral`. Transport-free: H4 packets in, H4 packets out, so the
  same host runs over the in-process radio, netsim, USB, or a test harness.
- **`src/device/classic_host.rs` (`ClassicHost`)** — the BR/EDR mirror:
  discoverability, inbound page acceptance, L2CAP signalling, per-PSM
  dispatch via a `ProtocolHandler` trait, with SDP as the first handler.
- **`trait HciTransport`** (`src/transport/mod.rs`) — formalizes what
  netsim/rootcanal/usb transports already did by convention, so
  `LiveScene<T>` (`src/transport/live_scene.rs`) can be generic over them.
- **Typed packet views** — `src/packets/hci_events.rs` and
  `src/packets/iso.rs`. Zerocopy structs replaced index-based parsing in the
  host path.

### Protocol work
- **Real P-256 ECDH** (`src/crypto/ecdh.rs`) — replaced a stub that sent 64
  random bytes as a "public key". Includes peer-point validation
  (CVE-2018-5383), which is what Android enforces.
- **ISO media plane** — `src/packets/iso.rs` (HCI ISO packets, SDU framing,
  sequence numbers), routing through the simulated radio
  (`src/controller/sim.rs`), a receive queue on `VirtualDevice`, and
  `send_audio`/`take_audio` script bindings.
- **Script access to real profiles** — `add_pacs()` / `add_ascs()` call the
  tested Rust registrars (including the ASE control-point handler), rather
  than a script hand-writing inert bytes. `advertise_service_uuid()` puts
  registrar-created services into the advertisement.
- **Custom advertising** — `advertise_service_data()`,
  `advertise_manufacturer_data()`, `advertise_connectable(false)` for real
  (non-connectable) beacons.

### Devices and pages
- 16 example devices served by `example`, including 9 added this session
  (HOGP keyboard/mouse/gamepad, cycling, pulse oximeter, weight scale, smart
  lock, fitness tracker, Eddystone).
- **`web/speaker/`** — an LE Audio Volume Control device with audio streamed
  to it as ISO SDUs and played through the volume gain. Linked into the site
  nav and index.
- `docs/android-peripherals.md` — profile-by-profile feasibility assessment
  and recommended build order.

## 2. Bugs found (all fixed unless noted)

The interop bugs are the most valuable artifact here; each passed unit tests
and failed against a real stack.

### Pairing against Android — eight distinct bugs in one chain
1. **Peer address type discarded** — byte 8 of LE Connection Complete was
   never read; SMP hardcoded `Random`. The type is mixed into the pairing
   crypto, so a public-address peer failed every time.
2. **Wrong self-identity** — SMP computed with the script engine's
   placeholder address instead of the on-air address (`set_identity` now
   stamps it).
3. **Responder SMP PDUs never sent** — `poll_smp_pdu`'s queue was never
   drained, so pairing stalled after the first reply.
4. **LE Long Term Key Request unanswered** — encryption could never start.
5. **Fake ECDH** — invalid curve points, rejected by Android's validation.
6. **No ACL fragmentation** — 65-byte SMP public keys sent as one oversized
   packet instead of 27-byte fragments.
7. **Key distribution before encryption** — Bumble named it exactly:
   "received key distribution on a non-encrypted connection".
8. **netsim address byte order** — see below.

### netsim reads the URL `address=` parameter LSB-first
Hit **three times independently** (Rust netsim path, browser path, Classic
example). A device asking for `CC:1E:57:00:00:06` advertises as
`06:00:00:57:1E:CC`; nothing can reach it and SMP computes with the wrong
identity. Fixed in each path — **these should be consolidated into one
shared helper**.

### wasm
- **`SystemTime::now()` panics on wasm32-unknown-unknown.** Every SMP nonce
  and ECDH keypair went through it, so browser-hosted devices could never
  pair. Worse, a panic inside a wasm-bindgen method leaves the object
  borrowed, so every later call throws "recursive use of an object". Fixed
  with a platform-appropriate clock (`js_sys::Date::now()` + counter).
- **`p256` broke the wasm build** — it pulls an older `getrandom` (0.2) that
  needs its own `js` feature. Fixed in `Cargo.toml`.
- **Chrome throttles background tabs to ~1 tick/sec.** A page-hosted device
  then misses protocol deadlines: Android connects, starts bonding, and
  times out after 30 s. Measured: 4 ticks in 3 s with the tab hidden versus
  30 expected. **Not fixed** — see remaining work.

### Other
- **ATT invalid handle range panicked** (`BTreeMap::range` with start > end)
  — any two-service device could crash the server. Now returns the
  spec-correct Invalid Handle error.
- **`server.value()` used the peer read path**, so a script could not read
  its own write-only control point. Added a host-side `GattDatabase::value`.
- **Nameless advertisements were impossible** — a full-size service-data
  payload (Quick Share, Eddystone, iBeacon) plus a name exceeds 31 bytes and
  the builder emitted a stub name field, so the advertisement was rejected
  and the device silently never transmitted.
- **Advertising type was always ADV_IND** — beacons appeared connectable.
- **Debug-key endianness** — the SMP debug constants are the spec's
  big-endian print; the session needs wire order.

### Open bugs
- **Mixed 16-bit + 128-bit services break central-side discovery.** The
  central sticks in "discovering characteristics" with phantom services
  (`9E6F`, `5B9E` — fragments of 128-bit UUIDs read as 16-bit). Triggered by
  `fitness_tracker`; a 128-bit service alone is fine. Under investigation by
  the device-sweep agent.
- **netsim leaves phantom devices** when a client's WebSocket drops — no
  disconnect is synthesized, so dead devices linger at the same address and
  a phone may try to connect to a ghost.
- **`subscribed` flag never flips to true** in status JSON, even with an
  active subscription (the truth is in the CCCD values).

## 3. Where LE Audio actually stands

Verified live against Bumble over netsim:

| Step | State |
|---|---|
| Advertising with a targeted ASCS announcement | works |
| PACS with a complete LC3 PAC record | works (record was too thin; fixed) |
| Pairing / bonding with Android | works |
| **ASE Config Codec → Codec Configured** | **works** (verified: `01 00` → `01 01 …`) |
| Config QoS → Enable → Streaming | unverified — the test client timed out, likely a stale connection holding the link |
| **CIS establishment** | **not implemented** — rootcanal supports it (`LeSetCigParameters`, `LeCreateCis`, `LeSetupIsoDataPath`) |
| **LC3 codec** | **not implemented** |

**No audio can reach a simble device from Android until CIS and LC3 exist.**
Android will show the device and may connect the profile, but there is no
media path. Do not present pairing success as audio support.

The ISO work already done carries SDUs over the *connection handle*, which is
fine for the in-process scene but rootcanal will not accept it — a real CIS
is required.

## 4. Remaining tasks, in recommended order

1. **Finish the ASE state machine verification** — Config QoS → Enable →
   Receiver Start Ready → Streaming, against Bumble. Cheap, and it tells you
   whether `src/profiles/ascs.rs` already covers the rest.
2. **CIS establishment** — handle the LE CIS Request event,
   `LeAcceptCisRequest`, `LeSetupIsoDataPath`, and move ISO onto the CIS
   handle. Verify against Bumble (it has `setup_cig`/`create_cis`) before
   involving Android.
3. **LC3** — decide: a Rust crate, or liblc3 compiled to wasm. Required for
   Android's audio to be decodable. This is a dependency decision, not a
   wiring job.
4. **Speaker page variations** — expose the device shape (VCS-only / full LE
   Audio sink / streaming source) and the media-plane transport (SDU over
   connection vs. real CIS) as explicit choices in the page rather than
   hand-edited scripts.
5. **Consolidate the netsim address byte-order fix** into one helper; three
   copies exist.
6. **Web Worker for page-hosted devices** plus a visible "tab hidden —
   device may miss protocol deadlines" warning. Today the failure is silent
   and looks like a Bluetooth bug.
7. **RFCOMM on `ClassicHost`** — the SDP record already advertises SPP on
   channel 3, a promise the device cannot yet keep. This turns Classic
   discovery into a working device an Android terminal app can talk to.
   Highest-value Classic item.
8. **The event path** (half-built, compiles): `push_event` / `on_event` with
   Rhai's documented event-handler pattern (persistent `Scope` +
   `bind_this_ptr`), plus `server.emit()` back to the page. The payload
   plumbing, `emit` binding and `on_event` detection are in;
   **the dispatch loop and wasm bindings are not**. This removes the `0xFF`
   sentinel hack from the VCP script and stops ATT events being discarded
   every tick.
9. **CodeMirror in the playground** — the current editor is a textarea with a
   highlight overlay, so errors cannot be marked on their line. Vendor it
   (the site is served from GitHub Pages and must work offline).
10. **Fix the open bugs** listed in section 2.

## 5. Lessons that cost real time

- **Filenames are not features.** Claims were made four times this session
  based on directory listings and greps, and corrected four times by reading
  the code. `src/classic/` (~13.6k lines, ~135 tests, a full L2CAP/SDP/RFCOMM
  stack) was described as "not existing" because one grep matched one file.
  Always read the module.
- **Unit tests do not prove interop.** Every pairing bug above passed the
  test suite. Both fake endpoints agreed with each other.
- **Use Bumble as the oracle.** It named two bugs outright in its logs. It is
  faster and more precise than testing against Android, and it removes the
  phone's quirks from the loop.
- **Capture the wire.** `SIMBLE_BTSNOOP=<dir>` on the MCP server writes
  Wireshark-readable btsnoop; Android's `logcat` and `dumpsys
  bluetooth_manager` give the peer's view. Several bugs were only visible
  there.
- **Verify the device is actually running** before debugging why it will not
  connect. Two long chases ended in "the process had exited" and "the tab was
  navigated away".

## 6. Useful commands

```bash
# netsim + emulator
~/Library/Android/sdk/emulator/netsim devices
~/Library/Android/sdk/platform-tools/adb logcat -d | grep -iE "bond_state|gatt"
~/Library/Android/sdk/platform-tools/adb shell dumpsys bluetooth_manager

# host a device natively on netsim (do NOT use a browser tab for this)
target/release/simble mcp   # then run_on netsim, add_peripheral, tick in a loop

# capture HCI
SIMBLE_BTSNOOP=/tmp/snoop target/release/simble mcp

# wasm build
RUSTFLAGS='--cfg getrandom_backend="wasm_js"' \
  cargo build --release --target wasm32-unknown-unknown --lib
wasm-bindgen --target web --no-typescript --out-dir web/pkg \
  target/wasm32-unknown-unknown/release/simble.wasm
```
