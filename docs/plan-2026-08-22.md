# Plan — 2026-08-22

A point-in-time plan from an early session; most items have since been done (CIS
and LC3 both exist now, for instance). Kept for the work it still names, the open
bugs, and the lessons.

## Remaining tasks, in recommended order

1. **Finish the ASE state machine verification** — Config QoS → Enable →
   Receiver Start Ready → Streaming, against Bumble. Cheap, and it tells you
   whether `src/profiles/ascs.rs` already covers the rest.
2. **CIS establishment** — handle the LE CIS Request event, `LeAcceptCisRequest`,
   `LeSetupIsoDataPath`, and move ISO onto the CIS handle. Verify against Bumble
   before involving Android.
3. **LC3** — a Rust crate, or liblc3 compiled to wasm; required for Android's
   audio to be decodable. A dependency decision, not a wiring job.
4. **Speaker page variations** — expose the device shape (VCS-only / full LE Audio
   sink / streaming source) and the media-plane transport (SDU over connection vs.
   real CIS) as explicit choices in the page rather than hand-edited scripts.
5. **Consolidate the netsim address byte-order fix** into one helper; three copies
   exist.
6. **Web Worker for page-hosted devices** plus a visible "tab hidden — device may
   miss protocol deadlines" warning. Today the failure is silent and looks like a
   Bluetooth bug (Chrome throttles background tabs to ~1 tick/sec).
7. **RFCOMM on `ClassicHost`** — the SDP record already advertises SPP on channel
   3, a promise the device cannot yet keep. Highest-value Classic item.
8. **The event path** — `push_event` / `on_event` with Rhai's event-handler
   pattern, plus `server.emit()` back to the page; removes the `0xFF` sentinel hack
   and stops ATT events being discarded every tick.
9. **CodeMirror in the playground** — the current editor is a textarea with a
   highlight overlay, so errors cannot be marked on their line. Vendor it (the site
   is served from GitHub Pages and must work offline).
10. **Fix the open bugs** below.

## Open bugs at the time

- **Mixed 16-bit + 128-bit services break central-side discovery.** The central
  sticks in "discovering characteristics" with phantom services (`9E6F`, `5B9E` —
  fragments of 128-bit UUIDs read as 16-bit). Triggered by `fitness_tracker`; a
  128-bit service alone is fine.
- **netsim leaves phantom devices** when a client's WebSocket drops — no disconnect
  is synthesized, so dead devices linger at the same address.
- **`subscribed` flag never flips to true** in status JSON, even with an active
  subscription (the truth is in the CCCD values).

## Lessons that cost real time

- **Filenames are not features.** `src/classic/` (~13.6k lines, ~135 tests, a full
  L2CAP/SDP/RFCOMM stack) was mistaken for "not existing" on the strength of one
  grep. Read the module before claiming what it does.
- **Unit tests do not prove interop.** Every pairing bug in this session passed the
  test suite; both fake endpoints agreed with each other.
- **Use Bumble as the oracle.** It named two bugs outright in its logs — faster and
  more precise than testing against Android, and it removes the phone's quirks.
- **Capture the wire.** `SIMBLE_BTSNOOP=<dir>` writes Wireshark-readable btsnoop;
  Android's `logcat` and `dumpsys bluetooth_manager` give the peer's view. Several
  bugs were only visible there.
- **Verify the device is actually running** before debugging why it will not
  connect. Two long chases ended in "the process had exited" and "the tab was
  navigated away".
