Testing

a script is a device — and a test

A SimBLE device is a Rhai script; add assert(...) and the same script becomes a test. It runs deterministically — no radio, no timing flakiness — so a failure is reproducible and the AI generate-check-fix loop actually converges. And the validated script is the artifact: it ships into netsim as a CI fixture unchanged. Edit below and press Run test.

Why this matters

Every assertion runs at build time in a fresh engine, against SimBLE's real GATT stack — so it checks the device your app will actually meet, not a mock. Because the run is deterministic, the exact same script an LLM writes, that you check here, and that CI runs against netsim are one file — no hand-translation between "the test" and "the fixture". Behavioural tests (connect, subscribe, assert a notification over time) build on the same primitive with wait_for and the scene APIs.

run_test(script) compiles and runs the script in a fresh SimBLE scripting engine; a failed assert(condition, "message") (or any runtime error) is reported here with its message. No netsim, no connection — pure, repeatable evaluation.
